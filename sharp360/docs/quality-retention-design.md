# SHARP360 高品質復元・共有期限設計

## 目的

正距円筒形式の360度写真1枚から、観測済み領域をできる限り高精度に3D Gaussian Splattingとして再構成し、7日間、30日間、60日間の共有期限を選択できるようにする。

## 復元の基本方針

### 事実として再構成できる範囲

- 撮影地点から見えている表面
- 水平方向360度
- 天頂・足元を含む入力画像に写っている範囲

### 事実として再構成できない範囲

- 建物、家具、樹木等の背後
- 撮影地点から遮蔽されている面
- 入力画像に写っていない空間

必要に応じて画像生成による補完を追加できるが、研究・教育用途では「推定補完」と明示し、観測済み領域と区別する。

## 品質プロファイル

| profile | 方向数 | 境界整理 | 深度尺度整合 | 用途 |
|---|---:|---|---|---|
| `balanced` | 6 | Voronoi境界クリッピング | DA360 | 推奨 |
| `maximum` | 8 | Voronoi境界クリッピング | DA360 | 実験的。6方向との比較検証が必要 |
| `prototype` | 4 | なし | なし | 無料CPU環境での動作確認 |

`balanced` と `maximum` は、SPAG-4DのSHARP 360型処理を参考に実装する。

処理順序:

```text
ERP形式360度画像
  ↓
重複付き透視投影画像を生成
  ↓
DA360でパノラマ深度を推定
  ↓
各方向にApple SHARPを適用
  ↓
Voronoi境界クリッピング
  ↓
方向間の深度尺度整合
  ↓
ワールド座標への回転
  ↓
単一PLYへ統合
```

## 共有期限

アップロード時に次の値から選択する。

```text
7
30
60
```

バックエンドは生成時刻と期限日時を保存する。

```json
{
  "created_at": "2026-06-02T00:00:00Z",
  "expires_at": "2026-06-09T00:00:00Z",
  "retention_days": 7
}
```

## 保存方式

### 検証用

```text
STORAGE_MODE=local
```

Hugging Face Spacesの一時ディスクを使用する。Space再起動後にファイルが消失するため、共有期限の保証はできない。

### 期限保証用

```text
STORAGE_MODE=supabase
```

Supabase Storageの非公開bucketを使用する。

```text
sharp360-scenes
```

閲覧時にはバックエンドが `expires_at` を確認する。

- 期限内: 短時間のみ有効な署名付きURLを返す
- 期限切れ: HTTP 410を返す
- 期限切れファイル: 遅延削除または定期削除

## 無料枠での運用

- GitHub Pages: フロントエンド
- Hugging Face Spaces CPU Basic: 検証用バックエンド
- Supabase Free Plan: 少人数の試験運用用ストレージ

高品質モードはGPUを前提とした方が現実的である。無料CPU環境では、処理時間、メモリ消費、依存関係のビルド可否を実測する。

## 実装順序

1. Hugging Face Spacesで `prototype` を起動する。
2. Supabaseの非公開bucketを接続する。
3. `retention_days`、`created_at`、`expires_at` を保存する。
4. 閲覧時の期限検査とHTTP 410を追加する。
5. 短時間署名付きURLを発行する。
6. 期限切れファイルの削除処理を追加する。
7. SPAG-4D型 `balanced` パイプラインを追加する。
8. `maximum` を実画像で比較検証する。
